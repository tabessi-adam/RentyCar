\section{Introduction}
In the last chapter, we explained the structure of the parts of our proposed solution and all the different features that make it work. Now, we start an very important step in building the system: the design phase. First, we will show how our solution works, then give a clear explanation of each use case using UML models.

\section{Physical Architecture Modeling}
\subsection{Deployment Diagram}
To illustrate the deployment of our solution, we used a deployment diagram that shows the physical arrangement of different materials and the distribution of components within nodes.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.8\textwidth]{chapters/images/deployment_diagram.png}
    \caption{Deployment Diagram}
\end{figure}
\newpage
Our deployment diagram consists of four main nodes:

\begin{itemize}
    \item \textbf{MySQL Database Management System:} \\
   Serves as our primary database server, responsible for storing and managing all critical application data. It handles various types of information, including vehicle details and specifications, user profiles and authentication data, reservation records and booking history, as well as office locations and their availability. Additionally, it manages system configuration and settings.
    
    \item \textbf{NestJS Backend Server:} \\
    Our backend infrastructure is built using NestJS and TypeScript, delivering a comprehensive set of services to support the platform. It provides RESTful API endpoints for all system operations and implements JWT-based authentication coupled with role-based authorization. The backend manages the business logic for vehicle management and offers services for data validation and transformation. It also  processes all business operations and manages the flow of data between the frontend and the database.
    
    \item \textbf{Angular Frontend Application:} \\
    Our frontend application, developed with Angular, delivers distinct interfaces tailored for different user roles. The Admin Dashboard enables system management and provides access to analytics, the Agent Interface focuses on reservation and customer management, and the Client Portal allows users to browse and book vehicles easily. Key features of the frontend include a fully responsive design compatible with all device types,

\end{itemize}

\begin{table}[H]

    \begin{tabular}{|p{3cm}|p{12cm}|}
        \hline
        Title & Manage Users \\
        \hline
        Primary Actor & Administrator, Agent \\
        \hline
        Description & The "Manage Users" use case allows administrators to manage all users and agents to manage clients within their office. Administrators have full access to all user management functions, while agents can only manage clients associated with their office. \\
        \hline
        Pre-conditions & \begin{itemize}
            \item User is logged into the system
            \item User has necessary rights to manage users
            \item For agents: user must be a client in their office

        \hline
        Post-conditions & User information is updated in the system \\
        \hline
        Possible Scenario & \begin{itemize}
            \item Administrator/Agent views list of users
            \item Administrator can add new users of any type
            \item Agent can add new clients for their office
            \item Administrator can modify any user's information

            \item Administrator can assign any user roles
            \item Agent can update client status
            \item System validates and saves changes
        \end{itemize} \\
        \hline
        Exception Scenario & \begin{itemize}
            \item Required user information is missing
            \item Email address is already in use
            \item Agent tries to manage user from another office
            \item Invalid role assignment
            \item System displays error message
            \item User corrects the information
        \end{itemize} \\
        \hline

\section{Conclusion}
Throughout this chapter, we have presented the design of our car rental management system. We established a deployment diagram illustrating the physical arrangement of different components and their interactions, including our NestJS backend and Angular frontend applications. Furthermore, through the specified use case diagrams, we clearly explained our system requirements. We also provided a global design through a class diagram describing the total system architecture. Finally, we addressed a detailed design of the use cases through sequence diagrams. This comprehensive design will guide us in the implementation phase of our project.
